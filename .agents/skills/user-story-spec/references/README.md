# References

This folder contains supporting documentation the skill can consult when reasoning, validating, or refining a product specification.

Use `references/` for:

- Internal repo or team rules.
- Technical or product criteria that affect the spec.
- Long guides that should not live in `SKILL.md`.
- Checklists used to validate output quality.
- Domain conventions and reusable decision rules.
- Summarized official documentation when relevant.

Practical rule:

- If the skill needs to read it to reason, validate, or decide, put it in `references/`.
- If it is only an input/output example, put it in `examples/`.
- If it is a reusable or copyable asset, put it in `assets/`.

Current references:

- `spec-workflow.md`: compact workflow and standard output areas.
- `execution-rules.md`: required and recommended behavior for the skill.
- `assumption-checklist.md`: rules for deciding which assumptions to list and refine.
- `spec-quality-checklist.md`: validation checklist for the initial spec output.
- `refinement-options-guide.md`: guide for generating four useful options plus `Other`.
- `applicable-skills-rules.md`: rules for selecting `Applicable skills` and `Skill-based validation`.
- `final-approval-loop.md`: rules for validating full agreement and showing final options.
- `spec-file-output-rules.md`: folder, naming, and spec file creation rules.
